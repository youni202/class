# 브라우저 실행 시나리오 (엔지비기업 실습 리허설)

실습가이드의 8개 장을 **실제 로그인된 브라우저에서 처음부터 끝까지 한 번 실행**하고, 화면 캡처와 실제 결과를 남기기 위한 시나리오입니다.
사람이 직접 해도 되고, 사용자 컴퓨터에서 도는 Claude 세션(Claude 데스크톱 앱 + Chrome 연동, 또는 이 폴더에서 `claude remote-control`)에게 맡겨도 됩니다.

## Claude 세션에 맡길 때 붙여넣을 지시문

```
현대엔지비/실행점검/브라우저_실행_시나리오.md 를 읽고 cap-01부터 cap-26까지 순서대로 내 Chrome에서 실행해 줘.
- 이미 로그인된 내 무료 계정만 사용하고, 유료 업그레이드·결제·새 계정 만들기는 하지 마.
- 요청문은 현대엔지비/실습자료/실습가이드.html 해당 장의 「복사할 요청」을 그대로 쓰고, [대괄호]는 바로 앞 단계의 실제 결과로 바꿔. 1장에서는 실습자료/1차시/01_사업아이디어/엔지비기업_상황자료.docx 를 첨부해.
- 각 cap마다 화면을 1280x800 정도로 캡처해 현대엔지비/captures/cap-XX.png 로 저장해. 이메일·계정명·프로필 사진은 가려.
- 결과는 현대엔지비/실행점검/실행기록.md 의 해당 칸에 사실대로 적어. 실행이 안 된 것은 "미실행"과 이유를 적고, 결과를 지어내지 마.
- 메뉴 이름이나 순서가 가이드와 다르면 실행기록의 "가이드와 다른 점"에 적어. 가이드 문구는 마지막에 한꺼번에 고칠게.
- 한도 안내가 뜨면 멈추고 나에게 알려 줘.
```

## 지킬 것

- 교육용 가상 사례(엔지비기업)만 입력합니다. 실제 거래처·회사 자료는 넣지 않습니다.
- 요청문은 한 번만 보냅니다. 생성 중에는 다시 보내지 않습니다.
- 「필요할 때만」 요청은 앞 결과에 해당 문제가 있을 때만 실행하고, 실행 여부를 기록합니다.
- Gamma AI 이미지·AI 편집은 크레딧이 남아 있을 때만 실행합니다. 남은 크레딧을 기록합니다.
- 캡처는 핀 번호가 가리킬 위치가 화면 안에 보이도록 찍습니다(아래 각 cap의 "화면에 보여야 할 것").

## 1장 · 사업 아이디어  (Gemini)

요청문: `실습자료/실습가이드.html` 1장 · 파일 폴더: `실습자료/1차시/01_사업아이디어/`

### cap-01 · Gemini 새 대화 열기

- 도구: Gemini (https://gemini.google.com)
- 할 일:
  1. gemini.google.com 접속 (수업 전 본인 Google 무료 계정으로 로그인)
  2. 가상 사례 설명: 엔지비기업(가상 무역·납품 업체) — 우리는 FAQ·답변 초안 정리 서비스를 기획하는 담당자
  3. 한 번에 한 동작: 강사가 시연 → 수강생이 같은 동작
- 화면에 보여야 할 것 (핀 번호 순서):
  1. 새 채팅 버튼을 눌러 빈 대화를 연다
  2. 당일 기본 모드 확인 — 유료 모델은 고르지 않는다
  3. 입력창이 비어 있고 이전 대화가 없는지 확인
- 성공 기준: 빈 입력창이 열려 있고 이전 대화 내용이 없다
- 막혔을 때: 한도 안내가 뜨면 멈추고 강사 가상 카드로 읽기·선택만 진행, 대체 실습으로 기록
- 캡처 저장: `captures/cap-01.png`

### cap-02 · 프롬프트① 붙여넣고 한 번만 전송

- 도구: Gemini (https://gemini.google.com)
- 보낼 요청: ①
- 할 일:
  1. 입력창의 「+」로 엔지비기업_상황자료.docx 첨부 (안 되면 건너뜀)
  2. 복사 버튼으로 아래 프롬프트 전체를 복사
  3. 입력창에 붙여넣고 처음과 끝이 들어갔는지 확인 (Ctrl+V / Mac Command+V)
  4. 한 번 전송하고 5분간 화면 유지 → Teams에 "완료" 또는 "멈춘 위치" 남기기
- 화면에 보여야 할 것 (핀 번호 순서):
  1. 프롬프트①을 한 덩어리로 붙여넣기 (처음·끝 포함 확인)
  2. 전송은 한 번만 — 생성 중 재전송 금지
  3. 응답: 세 안 비교표 + 여섯 항목 카드
- 성공 기준: 세 서비스 비교와 여섯 항목 카드가 나왔다. 수요·지불 의향은 가설로 표시, 새 수치·실적 없음
- 막혔을 때: 입력 위치·전송 여부 확인. 반복 생성/새 계정 금지. 강사 예시로 내용 작성만 진행
- 캡처 저장: `captures/cap-02.png`

### cap-03 · 비교 결과 읽기 → 카드 여섯 항목 복사

- 도구: Gemini (https://gemini.google.com)
- 보낼 요청: ② (필요할 때만 포함)
- 할 일:
  1. 공통 실습은 ② FAQ·답변 초안 정리·관리 서비스로 진행 (검증된 성공이 아니라 같은 문서를 발전시키기 위한 선택)
  2. 고객·제공물이 모호할 때만 프롬프트②를 실행. 이미 구체적이면 건너뜀
  3. 고친 카드 여섯 항목만 복사해 둔다 (비교표 제외)
- 화면에 보여야 할 것 (핀 번호 순서):
  1. 세 안 비교: ①FAQ 일회성 정리 ②정기 관리 ③문의 분석·월간 보고
  2. 카드 6항목: 고객·문제·가치·제공물·수익 가설·확인 질문
  3. 모호할 때만 프롬프트②를 같은 대화에 전송
- 성공 기준: 복사할 카드에 사람 검토와 [가설] 표시가 남아 있다
- 막혔을 때: 문제가 없으면 ②는 실행하지 않는다
- 캡처 저장: `captures/cap-03.png`

## 2장 · Canvas 문서  (Gemini Canvas)

요청문: `실습자료/실습가이드.html` 2장 · 파일 폴더: `실습자료/1차시/02_Canvas문서/`

### cap-04 · 새 대화에서 Canvas 선택

- 도구: Gemini (https://gemini.google.com)
- 할 일:
  1. 앞 대화가 아닌 새 대화에서 시작
  2. 도구 메뉴에서 Canvas 선택 → 입력창 옆에 Canvas 표시 확인
- 화면에 보여야 할 것 (핀 번호 순서):
  1. 입력창 아래 도구 메뉴를 연다
  2. Canvas를 선택한다 (메뉴 이름은 당일 화면 기준)
  3. 다음 프롬프트 「카드:」 문단을 내 카드로 바꿔 붙일 입력창
- 성공 기준: 입력창에 Canvas가 선택된 상태
- 막혔을 때: Canvas 버튼이 없거나 한도에 걸리면 제공 초안을 문서에서 고치고 "Canvas 대체 실습"으로 기록
- 캡처 저장: `captures/cap-04.png`

### cap-05 · 프롬프트③ Canvas 문서 생성

- 도구: Gemini Canvas (https://gemini.google.com)
- 보낼 요청: ③
- 할 일:
  1. 복사 → 「카드:」 문단을 앞에서 복사한 내 카드로 바꾸기
  2. 전송 후 제목과 문서 패널이 열릴 때까지 대기
- 화면에 보여야 할 것 (핀 번호 순서):
  1. 프롬프트③ 붙여넣기 — 「카드:」 문단을 내 카드로 교체 후 1회 전송
  2. 문서 제목 확인
  3. 소제목 6개: 고객·문제 / 서비스·가치 / 비교·차별점 / 운영·수익 가설 / 4주 계획 / 확인 질문
  4. 편집 가능한 문서 패널이 열렸는지 확인
- 성공 기준: 문서 패널·제목·소제목 6개·가상사례 표시·[가설] 표시. 일반 채팅 답변만 있으면 Canvas 미완료
- 막혔을 때: 2분 이상 막히면 강사 제공 Canvas 초안을 편집기에 붙여 부분 수정 연습 → 대체 실습 명시. 가입·결제 요구 금지
- 캡처 저장: `captures/cap-05.png`

### cap-06 · 프롬프트④ 「서비스·가치」 문단만 수정

- 도구: Gemini Canvas (https://gemini.google.com)
- 보낼 요청: ④
- 할 일:
  1. 수정할 문단을 드래그로 선택 → 나타나는 요청창에 붙여넣기
  2. 같은 Canvas를 유지 (새 문서 만들지 않음)
- 화면에 보여야 할 것 (핀 번호 순서):
  1. 「서비스·가치」 문단만 드래그로 선택
  2. 선택 문단의 요청창에 프롬프트④ 붙여넣기
  3. 다른 문단·출처·가설 표시가 그대로인지 확인
- 성공 기준: 대상 문단만 바뀌고 나머지는 유지됨
- 막혔을 때: 선택 요청창이 없으면 문단 안내 문구를 직접 수정
- 캡처 저장: `captures/cap-06.png`

## 3장 · 근거 조사  (Perplexity)

### cap-07 · Perplexity 새 검색 열기

- 도구: Perplexity (https://www.perplexity.ai)
- 할 일:
  1. perplexity.ai 접속, 무료 계정 로그인 확인

  2. 기본 Search 모드 — Pro·Research는 켜지 않는다
  3. 다음 장 조사 요청(프롬프트⑤)을 붙일 입력창
- 성공 기준: Search 기본 모드의 새 검색 입력창
- 막혔을 때: 검색이 막히면 공식 사이트를 직접 열어 같은 항목 확인. 못 찾은 내용은 미확인
- 캡처 저장: `captures/cap-07.png`

### cap-08 · 프롬프트⑤ 전송 → 출처 링크 찾기

- 도구: Perplexity (https://www.perplexity.ai)
- 보낼 요청: ⑤
- 할 일:
  1. 긴 답변을 다 읽기보다 공식 원문 링크를 먼저 찾는다
  2. 출처가 없으면 다음 단계로 완료 표시하지 않는다
- 화면에 보여야 할 것 (핀 번호 순서):
  1. 조사 요청 전체를 붙이고 한 번만 전송
  2. 답변 요약 — 그대로 믿지 말고 출처로 이동
  3. 출처 링크 2개 이상 (운영 안내 1 + 제품 자료 1)
- 성공 기준: 공식 운영 안내와 제품 자료의 원문 후보가 있다
- 막혔을 때: 강사 안내 후보: Zendesk 운영 원문 (FAQ 책임자·검토·갱신 절차만 확인용, 수요·효과 근거 아님). 두 번째 제품 자료는 직접 찾기. 못 열면 "원문 미확인"
- 캡처 저장: `captures/cap-08.png`

### cap-09 · 출처 원문 두 개 직접 열어 대조

- 도구: 브라우저 새 탭
- 보낼 요청: ⑥ (필요할 때만 포함)
- 할 일:
  1. 원문당 4분: 제목·날짜·관련 문단 → "AI 요약을 이 문장이 뒷받침하나?"
  2. 납품 업체에게 어떤 상황에서 해당되는지 확인
  3. 제품 기능 설명 ≠ 우리 고객의 지불 의향
- 화면에 보여야 할 것 (핀 번호 순서):
  1. 탭 2개: 원문 ①, 원문 ②
  2. 주소창 URL을 메모에 기록
  3. 제목·날짜 확인 (날짜 없으면 "날짜 미표시")
  4. AI 요약을 뒷받침하는 문단 찾기
- 성공 기준: 원문을 실제로 열었고 각 주장에 연결되는 문단을 찾았다
- 막혔을 때: 요약과 다르면 프롬프트⑥(조건부) 또는 해당 주장을 [미확인]으로. 못 연 자료는 확인한 수만 기록
- 캡처 저장: `captures/cap-09.png`

### cap-10 · 근거 메모 2건 작성

- 도구: 메모장/문서 편집기
- 할 일:
  1. 원문 하나마다 위 4항목을 짧게 작성 (사실 한두 문장)
  2. 한 자료가 말한 내용을 업계 전체로 넓히지 않는다
- 화면에 보여야 할 것 (핀 번호 순서):
  1. ① 확인한 사실 — 원문이 말하는 범위
  2. ② 문서와 날짜 — 기관·제목·날짜(또는 날짜 미표시)
  3. ③ 원문 URL — 내가 직접 연 주소
  4. ④ 적용과 한계 — 기획서에 쓸 내용 / 아직 모르는 점
- 성공 기준: 두 메모 모두 제목·날짜·URL·사실·한계가 있다. 못 연 자료는 "원문 미확인"
- 막혔을 때: 강사 가상예시의 빈 근거 칸을 조사 완료로 바꾸지 않는다
- 캡처 저장: `captures/cap-10.png`

## 4장 · 기획서 초안  (Gemini Canvas)

요청문: `실습자료/실습가이드.html` 4장 · 파일 폴더: `실습자료/1차시/04_기획서초안/`

### cap-11 · 2단계 Canvas 문서로 돌아가 메모 준비

- 도구: Gemini (https://gemini.google.com)
- 할 일:
  1. 도구 사이 자동 연동은 없다 — 사람이 확인한 메모를 직접 옮긴다
  2. 각 원문 메모를 복사 (URL·날짜·근거 위치 포함)

## 실행이 끝나면

1. `실행기록.md`의 「가이드와 다른 점」을 모아 `tools/content.js`(실습가이드 문구)와 `tools/build.py`(교안 화면 문구·핀 위치)를 고칩니다.
2. 핀이 캡처와 어긋나면 `교안.html` 주소 뒤에 `#edit`를 붙여 캡처 위를 클릭해 좌표를 읽고 `tools/build.py`의 pins 값을 고칩니다.
3. 다시 만들기: `python3 tools/build.py` → `node tools/forms.js` → `node tools/guide.js` (순서대로).
4. 캡처는 `교안.html`(핀 위에 표시)과 `실습자료/실습가이드.html`(각 장 「실제 화면」)에 자동으로 나타납니다.
